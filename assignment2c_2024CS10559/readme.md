# Assignment 2c: Parser for LITHP (OCaml-Yacc)

## Overview

This assignment implements a parser for a small LISP-like language (**LITHP**) using **ocamlyacc**.
The parser builds a raw abstract syntax tree (AST) from tokens produced by the lexer.

This repository builds on earlier work:

- `Bigint.ml` provides bigint support for numeric literals.
- `lexer.mll` provides tokenization.
- `parser.mly` provides grammar and parse actions.

---

## AST Representation

The parser outputs values of type `Ast.exp`:

- `A of atom` for atoms
- `L of exp list` for lists

Atoms are:

- numbers (`Num`)
- identifiers/symbols (`Id`)
- `t` (`True`)
- `()` (`Nil`)

Current top-level behavior parses a full file as a sequence of expressions and returns them as one list-like AST node (`L [...]`).

---

## Grammar Summary

Core non-terminals:

- `term` : atoms and keyword/operator symbols
- `expr` : either a `term` or a parenthesized `list`
- `elements` : zero or more `expr`
- `list` : `(` elements `)`
- `main` : `elements EOF`

This supports nested S-expressions and mixed atoms/lists.

---

## Tokens Expected from Lexer

The parser consumes tokens generated by `lexer.mll`, including:

- Parentheses and quote: `LEFTPAREN`, `RIGHTPAREN`, `QUOTE`
- Constants: `NUM`, `TRUE`, `NIL`
- Arithmetic/comparison/operator tokens
- Keywords: `quote`, `atom`, `eq`, `car`, `cdr`, `cons`, `cond`, `lambda`, `label`, `defun`
- Identifiers and compound `c[ad]+r` forms

## Build Instructions

Use the included `Makefile`:

```bash
make
```

This generates parser/lexer files, compiles all modules, and creates executable `main`.

---

## Run Instructions

Run with default input file:

```bash
make run
```

Run with a custom input file:

```bash
make run INPUT=your_input.lisp
```

Run interactively from stdin:

```bash
make run-stdin
```

Clear out all compiled files:

```bash
make clean
```

---

## Output Behavior

`main.ml` parses stdin and prints parsed expressions in readable form (one top-level expression per line).

If parsing fails, it prints:

- `Parse error`

---

## File Roles

- `Bigint.ml` : bigint arithmetic and conversion used by lexer/parser numeric literals
- `lexer.mll` : lexical analyzer specification
- `parser.mly` : parser grammar and semantic actions
- `ast.ml` : AST type definitions (`atom`, `exp`)
- `main.ml` : parser entry point and output formatting
- `Makefile` : reproducible build and run commands

---

## Notes

- The parser currently accepts multiple top-level expressions in a file.
- Comments and whitespace handling are done in the lexer.
- This implementation is focused on syntactic parsing, not evaluation.
